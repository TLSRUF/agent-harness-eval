# 실험 C 비교표 (exp_compare)

- 입력: default 120건, 3 120건, 4 120건, 5 120건, 7 120건. 최종 실행 로그만 읽는다(.partial, _final 제외). 읽기 전용, 모델 호출 없음.
- 열 이름 = 설정 max_turns(default = baseline의 max_turns 20). 도구 설명 default, 프롬프트 v1, 모델 haiku로 같다.
- 성공률은 채점 통과 기준이라 error_max_turns인데 통과한 실행도 포함한다(그 건수는 별도 행).

- max_turns 3: 지지(가설 수준): error_max_turns 79건이 모두 응답 수 == 설정값이고 응답 수 > 설정값인 success가 없다 -> 응답 수가 max_turns를 넘으려 할 때 중단하는 규칙(> max_turns)과 맞다. 응답 수 == 설정값인 success 38건이 있어 '응답 수 ≥ max_turns면 중단'(≥ 규칙)은 기각. 한계에 걸린 실행 79건 중 응답 수가 설정값과 같은 실행 79건
- max_turns 4: 지지(가설 수준): error_max_turns 34건이 모두 응답 수 == 설정값이고 응답 수 > 설정값인 success가 없다 -> 응답 수가 max_turns를 넘으려 할 때 중단하는 규칙(> max_turns)과 맞다. 응답 수 == 설정값인 success 46건이 있어 '응답 수 ≥ max_turns면 중단'(≥ 규칙)은 기각. 한계에 걸린 실행 34건 중 응답 수가 설정값과 같은 실행 34건
- max_turns 5: 지지(가설 수준): error_max_turns 9건이 모두 응답 수 == 설정값이고 응답 수 > 설정값인 success가 없다 -> 응답 수가 max_turns를 넘으려 할 때 중단하는 규칙(> max_turns)과 맞다. 응답 수 == 설정값인 success 23건이 있어 '응답 수 ≥ max_turns면 중단'(≥ 규칙)은 기각. 한계에 걸린 실행 9건 중 응답 수가 설정값과 같은 실행 9건
- max_turns 7: 확인 불가(한계에 걸린 실행 없음; 응답 수 == 설정값인 success 1건, success 응답 수 최대 7)
- max_turns 20: 확인 불가(한계에 걸린 실행 없음; 응답 수 == 설정값인 success 0건, success 응답 수 최대 7)
- 응답 수 = assistant 메시지의 고유 message_id 개수(baseline_report와 같은 정의). 같은 응답 안의 병렬 도구 호출은 한 번으로 센다.
- error_max_turns는 num_turns가 설정값+1로 보고될 수 있어(관찰: Day 3) 응답 수로 비교한다. 이 표는 관찰이며 한계 판정 규칙(>, ≥)은 가설이다.
- 칸의 건수가 작아(대부분 30건 미만) 해석에 주의. 판정이 안 되면 확인 불가로 표시한다.

| 설정 | 호출 | five_hour 시작 | five_hour 종료 | five_hour 델타 | seven_day 시작 | seven_day 종료 | 실행 수 | 비용 합계 |

- five_hour/seven_day는 구독 전체 사용량(탐침 호출로 읽음)이라 다른 사용이 섞일 수 있다. 해상도 0.01, 값마다 +-0.01 잡음이 관찰되어 한 배치 델타는 참고용이다.
- 비용은 정가 환산 추정치이며 구독 한도 소모와는 별개다. 실행 수/비용은 실행 로그 summary 시각이 탐침 시작~끝 사이인 실행의 합이다.
