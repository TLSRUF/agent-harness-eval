- 명령: `python -m src.eval.loader --check` (정답 풀이 적용 후 채점 + 무작업 채점), 준비된 쉬운 과제 E01~E12.

- 사용자 예측("1~2개는 채점기 버그로 실패")과 대조: 이 검증에서는 실패가 나타나지 않았다.
- 한계(확인 불가 범위): 이 검증은 pass 경로와 missing_output 경로만 실행한다. wrong_value / format_error / unexpected_change 경로와 토큰 경계, 정규화는 아직 실행해 보지 않았다 → 아래 단위 테스트에서 따로 점검하고 결과를 이어서 기록한다.
- 단위 테스트 첫 실행(수정 전): `pytest tests/test_graders.py tests/test_tasks.py` → 53개 중 11 실패, 42 통과.
  - 채점기/로더의 실제 버그 3건: (1) 프롬프트 도구 이름 검사(lint)가 한국어 조사가 붙은 이름("Grep을", "Grep으로", "Bash를", "Read로")을 놓침. 원인: 정규식 \b가 한글을 단어 문자로 취급. (2) contains_token이 한국어가 붙은 값("4줄", "20개", "c.txt입니다")을 독립 값으로 보지 못해 값은 맞고 형식만 틀린 답이 format_error 대신 wrong_value로 분류됨(진단 스크립트로 확인, 테스트는 이 케이스를 아직 안 잡음). (3) contains_token("count 4.5", "4")가 True(소수의 일부를 정수로 오인).
  - 테스트 자체의 버그 2건: test_normalize의 기대값 오류(중간 빈 줄은 내용이라는 설계와 어긋난 기대), test_text_file_paths의 변형별 폴더 이름 충돌(과제 8개 실패의 원인). 이 충돌이 test_text_file_paths의 뒤쪽 검증(format_error/wrong_value/missing_output/unexpected_change)을 가려서 그 경로들은 아직 검증되지 않았다.
  - 정답 풀이 자체의 실패는 없었다. 사용자 예측("채점기 버그")은 정답 풀이 검증에서는 안 맞았고 채점 부품 단위 테스트에서 3건으로 나타났다.
